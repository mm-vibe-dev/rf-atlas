# Packet protocol expansion: 0.6.0

Reviewed primary sources on 2026-10-09. Original RF Atlas implementations and authored synthetic fixtures remain MIT licensed. No third-party decoder source, binary, operational packet, identifier, address or information payload is bundled. Optional tools retain their own licenses and require an exact-distribution component audit before redistribution.

## Native AX.25 AFSK1200 subset

`rfatlas.packet.AX25AFSK1200Decoder` implements a receive-only, offline Bell 202 AFSK1200 modem from centered complex narrowband FM IQ. It resamples to 24 kS/s, uses a phase discriminator and 1200/2200 Hz energy comparison, evaluates twenty fixed-rate symbol clock phases, reverses NRZI, recognizes HDLC flags, removes stuffed zeros and validates CRC-16/X-25. Protocol verification additionally requires two through ten valid shifted AX.25 addresses, UI control 0x03, no-layer-3 PID 0xF0 and one through 256 information bytes. Empty or overlong information and malformed addresses are rejected even when the FCS is correct. Repeated timing hypotheses for the same physical frame are deduplicated; later identical transmissions remain separate frames.

The framing reference is the [TAPR AX.25 version 2.2 specification](https://tapr.org/pdf/AX25.2.2.pdf). The [Dire Wolf upstream documentation](https://github.com/wb2osz/direwolf/tree/dev/doc) documents VHF FM Bell 202 1200 baud use; its [repository](https://github.com/wb2osz/direwolf) identifies its GPL-2.0 license. RF Atlas does not embed or depend on Dire Wolf. The FCS implementation is independently authored, with the standard `123456789 -> 0x906e` check and an independently computed test oracle using Python's forward CRC primitive and bit reflections.

The current adapter intentionally declares the VHF 130–175 MHz organizational subset and 24 kS/s–2.4 MS/s inputs. Frequency is a compatibility constraint, never protocol evidence. It supports a bounded prefix of 24,000 symbols by default, at most 64 accepted frames, and no error correction, baud-rate search or continuous sample-clock tracking. The input must already be sufficiently centered and isolated; large carrier offsets, adjacent interference, non-Bell-202 or HF packet modes, G3RUH9600, FX.25, connected-mode frames and poor clocks can remain UNKNOWN. These are explicit unsupported cases, not proof that no packet was transmitted.

Only `AX.25` is verified. UI/F0 framing alone does not establish APRS application semantics. The implementation deliberately discards addresses and information after validation and returns only start sample, frame length, address count, UI/PID type and FCS validity. No packet addresses, text, position, station identity or decoded payload is stored by this adapter. Protection remains UNKNOWN because these checks provide no validated protection field.

### Controlled validation

Seven native tests pass on Windows. Eight clean synthetic IQ combinations span 24 kS/s, 48 kS/s, 250 kS/s and 1.024 MS/s, two start offsets, stuffed runs and both NRZI tone polarities. Additional tests cover identical later frames, work budgets, source binding, incompatible inputs, truncation, wrong baud, absent flags, incorrect FCS, invalid addresses with recomputed FCS, wrong control/PID, empty and overlong information.

The explicit negative corpus produced **0/200 verified protocols**: fifty independently seeded valid-sync, plausible-structure frames with damaged FCS, plus fifty noise, fifty pure CW and fifty unrelated BPSK IQ inputs. The valid-sync cases also assert that structural candidates were actually reached. This is a finite synthetic rejection measurement, not a universal false-positive bound or a measurement on real radio traffic. No field recall, weak-signal threshold or clock-drift performance is claimed.

## Additional audited rtl_433 model

`RTL433WH5Decoder` adds a separate optional Fineoffset-WH5-compatible wire-format subset while preserving `RTL433Decoder`'s WH2 contract. Both use upstream protocol 18, an explicit empty config, bounded file-only CU8 processing, isolated subprocess timeout/output limits, temporary cleanup and strict model/integrity/type/range checks. Missing executables remain optional failures. Merely returning JSON, a zero exit code or an arbitrary `mic=CRC` is insufficient; model-specific framing and integrity semantics must be audited before registration.

The tested local executable reports rtl_433 **25.12**. Its [version-specific Fine Offset source](https://github.com/merbanan/rtl_433/blob/25.12/src/devices/fineoffset.c) recognizes the WH5 47-bit frame with seven-bit FE preamble, type nibble 4, four payload bytes and CRC-8 polynomial 0x31, initial zero. WH5 temperature uses the unsigned offset encoding. This adapter restricts accepted temperature to -40 through 60 C, humidity to 0 through 100 and ID to an unsigned byte. The model label is upstream's wire-format interpretation; related Rosenborg hardware can share the same wire format with another temperature interpretation. A verified CRC/model event does not prove a unique manufacturer, sender authenticity or payload correctness. The source carries GPL-2.0-or-later notices; no source or executable is redistributed here.

The authored WH5 frame uses invented values and independently computes CRC by integer polynomial division. Actual Windows binary execution accepted valid CU8, rejected a one-bit CRC corruption, rejected a false preamble, rejected WH2 as WH5 and WH5 as WH2, and rejected eight seeded noise inputs. The earlier actual-binary WH2 tests still pass. All six external-adapter tests pass when `RFATLAS_RTL433` points at a trusted executable; two binary tests skip by design otherwise. Ubuntu's mandatory suite can validate parser and isolation behavior without installing rtl_433; Windows actual-binary success does not establish Ubuntu binary execution.

WH2A, WH24/WH65/WS69, TPMS, remotes and utility telemetry are not blanket enabled. Their upstream checks differ; the tested 25.12 WH2A path even documents an additional checksum as unimplemented. Broadening model acceptance would require separate authored RF vectors, per-model integrity audit and actual decoder execution. A checksum marker cannot substitute for those gates.

For digital voice, integrity and protection gates depend on the actual message type. The upstream [DMR privacy-indicator parser](https://github.com/lwvmobile/dsd-fme/blob/audio_work/src/dmr_pi.c) and [NXDN element processing](https://github.com/lwvmobile/dsd-fme/blob/audio_work/src/nxdn_element.c) illustrate different frame and field checks. Only a documented, validated field bound to a valid frame may establish protection metadata. No decryption, keys or key recovery are implemented. Decoder failure, noise-like audio and RF-band membership cannot establish encryption.
