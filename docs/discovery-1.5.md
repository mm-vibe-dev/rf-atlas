# RF Atlas 1.5 validation and operating limits

This release adds universal discovery scheduling, conservative signal characterization, native DMR control metadata and AIS position reports, audited weather telemetry, private annotations, and bounded acquisition/audio instrumentation. The release remains a prerelease because reduced audio gaps and broad analog recognition have not been demonstrated. All RF observations, raw recordings, identifiers, and detailed campaign logs remain local and excluded from distribution.

## Discovery and HF measurements

The default four envelope profiles schedule 883 segments from 0.5 to 1766 MHz. When all four are enabled, the scheduler chooses the least visited due segment before revisits. State survives restarts. Optional amateur, marine, aviation, weather, and sensor profiles supply investigation context; frequency alone never verifies a protocol. Only the envelope profiles are enabled by default. New catalogs allow bounded follow-up captures across general survey and supported protocol profiles; unsupported energy-only profiles remain survey-only. Existing capture permissions are preserved, and the ten new optional presets are appended in memory to the original complete preset catalog without rewriting the operator file.

Coverage accounting distinguishes attempted visits, valid visits, interval-union coverage, missing/invalid intervals, gross measured bandwidth including revisits, and the minimum successful visit count across configured regions. A completed pass is not continuous simultaneous reception. Weak and intermittent emissions can be missed during short visits.

HF uses the existing V4-family upconverter driver path without direct-sampling, driver, DLL, EEPROM, or bias-tee changes. Two offset 2.4 MS/s acquisitions cover each segment using measured interior Welch FFT bins. The outer 20 percent and center 2.5 percent are excluded; the other tuning supplies the missing center region. Startup samples are discarded. Each raw acquisition is capped at eight seconds plus startup discard, then removed. Incomplete, constant, nonfinite, or heavily clipped streams fail rather than being interpolated into valid measurements. Outside HF, nonfinite rtl_power output is preserved with its command and parser diagnostics before a bounded independent floating FFT retry. Accepted settings identify the actual backend, integration, and rejected sub-acquisition; the retry must independently satisfy coverage checks. Numeric zero gain is rejected because rtl_sdr interprets it as automatic gain.

## DMR recovery

The earlier Python timeline tool and historical recordings were located and independently replayed. The former tool reports three direct CRC passes and combined repeated-copy results on the short historical recording. Its permissive slot/FEC and post-CRC repair rules are broader than the new acceptance contract. One direct frame survives the stricter native path: BS data synchronization, unique Golay slot decoding within three errors, converged BPTC, and an unmodified CSBK CRC. Removing IQ DC before channel filtering was essential to reproducing it.

The accepted historical frame contains DMR CSBK, a recovered color code, Motorola Capacity Plus opcode/FID, and rest-channel metadata. Separate fresh hardware captures also verified native control frames; detailed RF observations remain private. That value does not establish a physical RF channel mapping or logical channel number. Timeslot, voice, encryption, and current activity remain unverified. RF Atlas previously had no native Golay/BPTC/CSBK adapter, so its UNKNOWN result was expected. The new adapter operates on RF Atlas-managed CU8 samples at arbitrary frequencies and supports bounded internal frequency-offset recovery.

Optional DSD-FME consumes a temporary mono signed PCM16 48 kHz discriminator WAV, with null output and no receiver, trunking, networking, or speech-file options. Its console synchronization indications remain diagnostics because an audited per-frame integrity contract is unavailable. Temporary working files are isolated and removed; time and output quotas apply. The executable is neither required nor redistributed. Native DMR provides verification independently.

References: [ETSI DMR air interface](https://www.etsi.org/deliver/etsi_ts/102300_102399/10236101/02.06.01_60/ts_10236101v020601p.pdf), [DSD-FME source and licensing](https://github.com/lwvmobile/dsd-fme/blob/audio_work/COPYRIGHT), [V4L hardware description](https://www.rtl-sdr.com/rtl-sdr-blog-v4-end-of-line/).

## Characterization and decoder boundaries

The existing DSP benchmark, features, and classifier remain unchanged. A hierarchy records ANALOG, DIGITAL, MIXED, NOISE_CANDIDATE, or UNKNOWN with evidence and explicit uncalibrated uncertainty. Verified RDS yields MIXED WFM/RDS; other supported verified protocols yield DIGITAL. Unsupported SSB/QAM/OFDM and ambiguous carriers may abstain. No experimental ML promotion is made.

The unchanged 360-case two-seed corpus produced 57.8 percent overall family accuracy, 47.2 percent abstention, and 92.6 percent accuracy among accepted decisions. No noise fixture received an analog/digital label (0/36). The carrier fixtures include four false analog hypotheses; eight digital fixtures received analog hypotheses. Exact modulation-label accuracy was 66.7 percent. Mean processing latency was 79 ms, p95 166 ms, with 15.9 MB peak Python-traced allocations (not process RSS). These results describe deterministic fixtures, not live identification accuracy, and do not demonstrate a classifier improvement.

Native AIS handles CRC-verified 168-bit Class A position reports (types 1, 2, 3) with GMSK/NRZI/HDLC processing. Valid MMSIs and valid position fields are retained only under identifier policy. Other AIS types, vessel names, and live reception are not implied by the test-only waveform. [ITU AIS specification](https://www.itu.int/rec/R-REC-m.1371/en).

The optional rtl_433 adapter retains the audited WH2/WH5 paths and adds WH24 temperature, humidity, battery, rain, and wind fields. Its exact model and upstream CRC-plus-sum contract are checked; arbitrary JSON model labels are not accepted. Synthetic CU8 fixtures exercise the actual installed executable, including corrupt CRC and checksum negatives. Soil telemetry and the rest of rtl_433's protocol list are not automatically trusted. External executable fingerprints accompany attempts. [Audited Fine Offset decoder source](https://raw.githubusercontent.com/merbanan/rtl_433/master/src/devices/fineoffset.c).

AX.25, RDS, and sensor frequency allocations now influence routing rather than excluding otherwise compatible recordings. Modulation compatibility outranks broad band hints within the bounded attempt budget. ADS-B retains its 1090 MHz decoder constraint. Decoder budgets, sample-rate/duration limits, failures, availability, synchronization, CRC results, and unsupported protocol lists remain explicit. P25, NXDN, D-STAR, C4FM, M17, UAT, ACARS, FT8/FT4/WSPR, RTTY/PSK31, radiosondes, weather satellites, and NRSC-5 are not verified decoders in this release. NOAA POES APT satellites were retired in 2025 and are not represented as active presets. [NOAA operational status](https://ospo.noaa.gov/operations/poes/).

## Private inventory and audio

Schema 10 adds private names, notes, tags, and favorites without rewriting historical observations. A pre-migration catalog backup is created. Annotations never become verified identities. The console distinguishes evidence-based signal classes from frequency-based family hints, uses correct UTF-8 activity text, and does not infer inactivity while scanning elsewhere. Existing tuning, investigation history, frames, and monitor controls are preserved.

Audio acquisition and DSP now use separate bounded stages. The input queue holds at most four 100 ms blocks and drops stale input under overload. Telemetry reports host delivery gaps, input age, queue drops, DSP overruns, transport sequence drops, fetch latency, playback occupancy, and underruns. CU8 host delivery timing does not prove physical USB sample continuity. Existing browser latency limits remain bounded. Six reception modes and controls retain regression coverage; live before/after results belong in the local completion report. Three steady-state samples per version showed zero underruns for the baseline and one, zero, zero for the new path. The first new sample overlapped package tests. Later quiet-host samples were stable, but reduced gaps were not demonstrated. All six modes delivered live browser PCM; this does not establish intelligibility or identify an emission.

## Validation record

Final Windows source testing passed 259 tests, including the actual installed rtl_433 fixture path. Ubuntu 24.04 source and installed-wheel testing each passed 246 tests with five optional/platform skips; the isolated Windows wheel passed all 246 public tests. The source tree, wheel, sdist, Ubuntu regression, installed-wheel tests, preservation checks, and live campaign are independently gated. Detailed private evidence is stored under the local campaign report directory and is deliberately excluded from this public document. Final measured coverage, acquisition duration, live discovery counts, resource use, audio comparison, commit hashes, and limitations will be recorded after completion; no fixture result counts as a live discovery.
