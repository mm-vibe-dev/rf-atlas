# Architectural research and third-party attribution

Inspected arall/sigint at commit 174003a7887e09c35ce6ec9fd1ac79612cb94dc1. The recursive repository tree did not contain a LICENSE file; requesting the root LICENSE returned 404. This is not permission to reuse source. No source, assets, sample data or dependency files were copied into RF Atlas. Original RF Atlas code is licensed under MIT; that grant does not apply to research repositories or external binaries.

The following observations informed architectural boundaries, not implementation reuse:

- The [capture interface](https://github.com/arall/sigint/blob/174003a7887e09c35ce6ec9fd1ac79612cb94dc1/src/capture/base.py) owns one source and emits frames to parser callbacks. RF Atlas instead uses an injected finite CLI backend for its current checkpointed scans, keeping offline DSP independent of capture.
- The [architecture document](https://github.com/arall/sigint/blob/174003a7887e09c35ce6ec9fd1ac79612cb94dc1/docs/architecture.md) separates capture, parsers and scanner orchestration, and discusses autonomous short-burst sensors alongside centrally tasked longer receptions. RF Atlas adopts separation of concerns for one local receiver. Remote transport and multiple-sensor scheduling are outside its roadmap.
- The inspected [modulation module](https://github.com/arall/sigint/blob/174003a7887e09c35ce6ec9fd1ac79612cb94dc1/src/dsp/amc.py) uses envelope, frequency and spectral features for heuristic modulation. RF Atlas implements its own limited statistical estimator, validated with independently generated synthetic IQ. It does not claim protocol confirmation or copy that decision tree.
- The [SQLite implementation](https://github.com/arall/sigint/blob/174003a7887e09c35ce6ec9fd1ac79612cb94dc1/src/utils/db.py) uses session/agent provenance, indexes and WAL. Its code describes a unified store, whereas the architecture document still describes per-session files. RF Atlas keeps its existing authoritative local schema; the inconsistency illustrates why documentation and implementation must both be examined.
- The [triangulation notes](https://github.com/arall/sigint/blob/174003a7887e09c35ce6ec9fd1ac79612cb94dc1/docs/triangulation.md) combine correlation, a log-distance model and multi-node optimization, emphasizing receiver calibration and multipath limits. This historical research does not establish a product requirement: RF Atlas excludes localization and multiple-receiver observations. Relative RTL power is not an absolute distance measurement.

Feature techniques used here—Welch spectral estimation, power-weighted moments, envelope variation, instantaneous phase differences and histogram modes—are general DSP methods implemented independently with NumPy/SciPy. This initial classifier covers only a few waveform hypotheses. Broader protocol support requires separate evidence validation. Distributed sensing and triangulation are excluded; RF Atlas does not incorporate the researched project's mesh or ATAK integrations.
