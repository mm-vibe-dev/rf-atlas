# Protocol decoder evaluation for 0.5.0

Reviewed upstream primary sources on 2026-10-09. This is an integration decision record, not a claim that every listed decoder runs in RF Atlas. No third-party source, binaries, captured traffic or pretrained assets were copied into the distribution. Original adapters and synthetic fixtures remain MIT licensed. Optional tools retain their own licenses; subprocess use does not relicense those tools. Audit exact distributions and component notices before redistribution.

Upstream [rtl_433 usage](https://github.com/merbanan/rtl_433#running) documents file input, protocol restriction and JSON output. Its supported device list includes weather sensors, TPMS, remotes and utility telemetry; those are upstream capabilities, not blanket RF Atlas protocol support. [readsb usage](https://github.com/wiedehopf/readsb#usage) documents offline `ifile` with UC8/SC16 formats. No comparable CPU benchmark was run for these products. Low-footprint judgments reflect architecture/dependencies, not measured decoder accuracy or throughput. RF Atlas retains its existing acquisition backend and never delegates direct USB ownership to the offline rtl_433 adapter. Other products' upstream RTL support does not prove compatibility with this machine's exact driver/runtime configuration.

## Audited rtl_433 integration

`rfatlas.external_decoders.RTL433Decoder` restricts protocol selection to upstream protocol 18 and accepts only `Fineoffset-WH2` events with `mic=CRC`, typed sensor fields and plausible ranges. Other variants and generic checksum events remain unverified. The [upstream Fine Offset implementation](https://github.com/merbanan/rtl_433/blob/master/src/devices/fineoffset.c) checks a 48-bit WH2 packet, FF preamble, type nibble 4 and CRC-8 polynomial 0x31 with initial zero. It emits the accepted model only after those checks. A CRC-8 has limited collision resistance; a valid event establishes protocol-level evidence, not sender authenticity or guaranteed payload correctness.

The adapter writes bounded translated IQ to a temporary CU8 file, uses an explicit empty configuration to suppress inherited outputs, selects file input, applies a timeout and removes temporary files. It uses an isolated subprocess boundary rather than shell interpretation: stdout/stderr spool to temporary files, aggregate output over one MiB is rejected, and Windows jobs or Linux process groups terminate descendants. Linux also retains the parent-death guard. The quota is polled, so a fast process can transiently exceed the limit on disk between polls; excess output is never accepted or loaded into memory. Operators supply a trusted executable; malformed JSON, missing fields, unexpected models and absent binaries fail conservatively. External output counts represent returned events, not every RF frame searched. Source IQ digest and analysis offset are retained separately. No protection indicator is supplied, so protection remains UNKNOWN.

Local Windows validation used an already-installed rtl_433 25.12 executable, with no downloads or driver changes. The authored synthetic PWM frame `ff4120d232b8` represents ID 18, temperature 21 C and humidity 50%. It decoded through actual CU8 file processing. A one-bit CRC corruption and false preamble were rejected; eight seeded noise-only inputs produced zero verified events. Four adapter tests passed, including parser/configuration/cleanup boundaries. This is a small controlled validation, not a broad real-world reliability study. By default the binary-dependent test skips unless `RFATLAS_RTL433` is set; core tests need no external binary.

## Voice-radio protection evidence is protocol specific

DSD-FME's [README and installation notes](https://github.com/lwvmobile/dsd-fme/blob/audio_work/examples/Install_Notes.md) describe a Linux-oriented dependency stack and Windows/Cygwin options. The existing local portable help supports DMR, P25 Phase 1/2 and NXDN48/96, while flagging NXDN modes as requiring explicit selection. Offline input is mono discriminator WAV or supported symbol capture, not arbitrary CU8. Converting RF IQ to correctly filtered discriminator audio is a separate evidence-sensitive stage. The local package's presence or ability to print help does not establish valid frame decoding.

DMR: [short link-control processing](https://github.com/lwvmobile/dsd-fme/blob/audio_work/src/dmr_flco.c) gates one route on Hamming results and CRC-8. [Privacy-indicator handling](https://github.com/lwvmobile/dsd-fme/blob/audio_work/src/dmr_pi.c) contains manufacturer-dependent algorithm/key/MI interpretation and different checksum gates. Do not promote every printed privacy line into verified metadata. P25: [SDRTrunk header fields](https://github.com/DSheirer/sdrtrunk/blob/master/src/main/java/io/github/dsheirer/module/decode/p25/phase1/message/hdu/HeaderData.java) illustrate algorithm/key/MI metadata; header integrity and message type must accompany interpretation. NXDN: [element processing](https://github.com/lwvmobile/dsd-fme/blob/audio_work/src/nxdn_element.c) supplies separate call/cipher fields; its framing/checks differ from DMR. RF Atlas does not currently integrate these parsers or claim DMR/P25/NXDN verification. No keys, decryption or key extraction are implemented.

## AIS quality caveat and next integration gate

The current [AIS-catcher README](https://github.com/jvde-github/AIS-catcher#flagged-messages-and-filters) explicitly describes checksum/size quality flags and explains that enabling filtering alone does not exclude errors: `EXCLUDE_ERRORS` defaults to `none`. It documents `CRC_CHECK on` for ingress rejection. Plain NMEA cannot preserve error flags when its checksum is regenerated. A future adapter must pin a tested version, require strict CRC handling and reject bad-checksum or undersized frames before generating verified evidence. Matching a maritime frequency, valid NMEA XOR or plausible vessel fields is insufficient.

For any additional decoder: first obtain author-generated or clearly licensed valid/invalid RF vectors, test actual offline execution on both targets, bind integrity evidence to the exact input, measure noise/false-sync rejection, and document license and protection semantics. Missing binaries must remain optional failures. No current evidence justifies converting an unrecognized narrowband recording into a named voice protocol.
