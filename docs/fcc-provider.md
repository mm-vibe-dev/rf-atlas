# Local FCC licensing context: 0.7.0

`rfatlas.fcc.LocalFCCProvider` is an optional offline provider over a separate normalized SQLite file. The operational RF Atlas catalog remains unchanged. No lookup transmits a frequency, location, capture or user identifier. The provider creates nothing when its database is missing and returns an explicit unavailable result for missing, locked, corrupt or incompatible databases.

`lookup(frequency_hz, tolerance_hz=0, include_location=False, limit=25)` uses an indexed frequency interval, returns at most 100 matches plus a truncation indicator and preserves service, licensee, callsign, status, source and source update date. Tolerance is explicit and capped at one MHz. Coordinates and location text are excluded unless the caller explicitly requests them. All statuses are preserved; an expired/cancelled record is not silently treated as current. No identity, protocol, current activity or legal authorization is inferred from a frequency match.

Trusted local CLI lookup: `rf-atlas fcc-lookup localnormalized.sqlite 100M --tolerance-hz 1000`. Add `--include-location` only when location fields are needed. The path selects the separate normalized context database; no online lookup or FCC archive download occurs.

`ingest_assignments(path, rows, source=..., updated=...)` streams validated normalized dictionaries. Required fields are `frequency_hz`, `service`, `licensee`, `callsign` and `status`; optional fields are paired `latitude`/`longitude` and `location`. Source and ISO update date/timestamp are mandatory. One transaction replaces only the named source, retaining other sources; malformed input or a row-budget failure rolls back the replacement. Default budget is 100,000 rows and maximum configurable budget is one million. This is a normalized import interface, not an FCC bulk ZIP parser. Select a dedicated private context database; the importer refuses an existing unversioned database with other tables and unsupported future schemas.

Seven authored synthetic tests validate optional absence, frequency/tolerance boundaries, source timestamps, location redaction, output limits, ordering, status preservation, source replacement, rollback, invalid input and refusal to modify unrelated/future databases. No real licensing records or person's location were downloaded into the repository. A returned source date is provenance; it is not a claim that the file is the newest FCC release.

## Upstream assessment

[tgies/uls](https://github.com/tgies/uls) provides local SQLite callsign lookup, imports and structured output, with MIT/Apache-2.0 licensing. Its documented supported services prioritize amateur HA/HV and GMRS ZA; it is not a comprehensive land-mobile frequency assignment provider. Callsign search and service entitlement must not be expanded into invented site/frequency assignments. RF Atlas does not depend on or bundle this Rust CLI.

The requested [FCC public-access downloads page](https://www.fcc.gov/wireless/data/public-access-files-database-downloads) returned HTTP 403 to the research tool. The official [FCC ULS data overview](https://opendata.fcc.gov/Wireless/FCC-Universal-Licensing-System-ULS-/x28i-i4z4) confirms downloadable pipe-delimited license/application data and links weekly/daily files. The official [public-access introduction](https://wireless.fcc.gov/uls/documentation/pa_intro24.pdf) describes site-based joins, including unique system identifier, location, antenna and frequency keys. Its age means a production importer must recheck the currently published layout before hardcoding any positional fields.

## Accurate bulk-ingestion plan

1. Explicitly choose license datasets and service codes from the current FCC download index; record archive URL, source date, retrieval time, byte count and SHA-256 in local provenance. Do not substitute application records for granted license records or advertise complete US spectrum coverage.
2. Read current FCC field definitions. Parse the correct pipe-delimited layouts, including empty fields and action/deletion records. Join license header/status, appropriate licensee entity, frequency assignment and transmitter location records by stable FCC keys. Frequency rows may additionally require location/antenna/frequency numbers. Preserve duplicate assignments across sites and licensees.
3. Normalize frequency units to Hz and coordinates with explicit hemisphere handling. Keep missing coordinates missing; never use the licensee mailing address as the transmitter site. Exclude contact, private user and unnecessary personal fields from normalized outputs. Amateur/GMRS service privileges alone do not establish a particular transmitter assignment.
4. Build each source in an isolated staging database. Validate joins, counts, malformed rows, dates, deletion handling and representative records against official FCC lookup before atomic promotion. Daily updates require a verified contiguous sequence after a compatible full snapshot; gaps require a new full snapshot rather than an invented update date.
5. Export only the normalized fields accepted here, import with a truthful source/update value and keep the local database ignored by Git and outside release artifacts. Measure full-dataset import/query resources separately. No full FCC ingest, current assignment accuracy, real-dataset performance or comprehensive LMR coverage is claimed for 0.7.0.
