# RF Atlas 1.4 validation

RF Atlas 1.4 adds an actual continuous I/Q receiver to the Discovery Console. Select any catalog signal, open its detail, and choose **TUNE & MONITOR**. UNKNOWN classification never prevents reception. The existing integrating tuner, inventories, SQLite schema 9, captures, SigMF, optional DuckDB, scanner profiles and frozen DSP classifiers remain available.

The monitor starts a single owned `rtl_sdr` process and reads CU8 through a pipe. It never continuously writes I/Q or audio files. Hardware frequency, sample rate, manual gain and PPM changes restart that owned process; DSP settings change at an epoch boundary. The display only reports a tuned state after samples arrive. A global receiver lock remains held until the process is killed and reaped, including failure paths. Windows Job Objects and the existing Linux parent-death wrapper bound child lifetime.

Auto Survey pauses before live acquisition and retains its completed measurements and profile preferences. Return to Discovery stops audio and acquisition, releases the receiver, and resumes the previous survey when Restore Auto Survey is enabled. Explicit survey stop cancels restoration. Browser heartbeats are separate from ordinary status polling: abandoned monitoring expires after 30 seconds. A tab that is hidden or has left the monitor does not indefinitely renew its lease. Application shutdown closes the owner without restarting discovery.

The live panel includes a labeled frequency scale, peak hold, noise estimate, relative RF meter, filter overlay, FFT zoom/pan, clickable spectrum/waterfall tuning, bounded waterfall history, floor/range/contrast/update controls and historical context. Levels are uncalibrated relative dBFS and peak-bin SNR, not absolute dBm or transmitter identity. A peak below 10 dB estimated SNR is labeled inactive or below threshold. Quiet digital bursts can still be missed. Audio RMS is explicitly separate from RF power.

AM uses magnitude-envelope detection. NFM and WFM use a conjugate-product phase discriminator. USB and LSB use a complex channel filter restricted to the selected sideband, followed by real conversion. CW uses a 700 Hz beat oscillator. Stateful FIR decimation, channel/audio IIR filters and rational 48 kHz resampling carry their history across blocks. Mode-specific filter limits reject settings outside the usable I/Q passband. Deterministic independently generated tones validate all six modes; only WFM has been checked against a locally received public broadcast. Stereo is unavailable. Frequency context supplies a labeled mode recommendation, never protocol verification.

Manual RF gain uses the existing receiver gain enumeration. Hardware AGC remains unavailable. Audio controls include volume, mute, software gain, optional audio AGC, optional DC removal, audio cutoff and bypassable 50/75 microsecond WFM de-emphasis. Squelch opens 2 dB above threshold and closes after three 100 ms blocks below threshold minus 2 dB. It gates audio while I/Q, FFT and waterfall continue. PCM is limited below full scale. PPM is an explicit user correction with unverified calibration accuracy; it does not overwrite another signal's preset.

The monitor excludes numeric zero gain: [rtl_sdr reserves zero for automatic gain](https://github.com/rtlsdrblog/rtl-sdr-blog/blob/master/src/rtl_sdr.c), even though zero is present in the hardware's gain enumeration. Positive manual steps remain available. Validation rejects zero before disturbing receiver ownership; the existing rtl_power tuner retains its separate gain contract.

Listen creates and resumes a browser AudioContext only after a user gesture. Bounded PCM cursor requests stream directly from memory. The server retains at most one second of PCM and returns at most 300 ms per request; the browser discards excess scheduling backlog. Retuning invalidates old audio epochs. Stop Listening closes the context. No playback starts when viewing historical observations. Browser scheduling and output latency are measured separately from acquisition/DSP delay; a physical speaker or human listening assessment is not established by headless browser playback.

Periodic live decoder checks use bounded transient I/Q windows and the existing synchronization/checksum-validated registry. Manual Decode requests an immediate check. Frame bytes and identifiers obey the existing independent privacy preferences. Results label their transient sample digest and remain separate from historical catalog evidence. This release does not automatically turn live checks into saved acquisitions, station counts or classification revisions. Signal-specific user presets and bounded session summaries persist privately; raw continuous streams do not. Continuous recording and digital voice playback are unavailable.

AUTO OPTIMIZE evaluates three manual gains and two small offset alternatives, scores estimated SNR with a clipping penalty, and restores the original configuration before presenting a recommendation. Unstable, weak or clipped input can produce no recommendation. Apply and Restore are explicit actions, and recommendations never overwrite a preset. Mode and filter remain manual recommendations. This is assisted reception, not a calibrated demodulation-quality optimizer; changing RF activity can affect its result.

The rtl_433 investigation reproduced a file-path inference defect. Its parser reads rate and content tokens from the entire input path, so a temporary directory containing `9k` can override the intended rate despite `-s`. A directory containing `am` can change content interpretation. The adapter now forces **CU8, I/Q, and the validated sample rate** in the read-file specification. Controlled misleading-directory fixtures recover both supported Fine Offset models while rejecting corrupt CRCs. Before repair, one of 100 repeated valid fixtures returned no event; after repair, all 200 positives decoded and all 200 corrupted fixtures were rejected. This repair does not relax CRC or accept a model label as sufficient evidence. See upstream [file-format parsing](https://github.com/merbanan/rtl_433/blob/master/src/fileformat.c) and [read-file help](https://github.com/merbanan/rtl_433/blob/master/src/rtl_433.c).

The four earlier AM acquisitions contain non-finite values in the original receiver CSV, across 12 rows and 76 bins. Those rows remain rejected and unchanged. New stable diagnostics distinguish non-finite/malformed power, empty/malformed rows, coverage gaps and incomplete coverage; inventory quality and campaign reports retain those dispositions. A synthetic Windows `-nan(ind)` fixture confirms that no zero replacements or partial valid observations enter the catalog. The upstream [rtl_power implementation](https://github.com/rtlsdrblog/rtl-sdr-blog/blob/master/src/rtl_power.c) accumulates integer FFT power and uses wall-clock reporting boundaries. Integer overflow is a plausible AM hypothesis, not a proven diagnosis of the installed binary. Drivers, DLLs, USB and VM settings were not changed.

The matched ABBA comparison uses identical dwell, integration, gain, crop, resolution, ranges and detector. The prior function measured 8.3 valid MHz in 39.743 seconds (seven of eight valid); the current function measured 10.3 MHz in 39.997 seconds (eight of eight valid). This reverses the earlier imbalance, where the current arm contained the invalid visit. Excluding the affected range in both arms is the appropriate sensitivity comparison; no causal scanner speed gain or loss follows from these small trials. Process startup, tuning, settling, transfer and FFT remain combined inside the external tool. The field campaign measures parsing/detection/database overhead separately. Internal tuning and FFT time cannot honestly be separated without instrumenting the external binary. Detection sensitivity and the acquisition algorithm remain unchanged.

The new bounded campaign used the same ten regional windows and manual gain as the 1.3 field run, with Quick exploration for 90 seconds followed by Smart visits. Its 360.001 seconds include cooldown and a final operation reserve. It produced 33 visits, 29 valid and four invalid; 46.5 MHz valid gross coverage including revisits; 12.25 MHz unique valid coverage; 128 observations; 48 candidate channels; seven completed investigations; two RDS-verified recordings and two retained PI systems; zero identified devices; and 46 UNKNOWN channels in that isolated campaign. Queue wait averaged 2.430 seconds, with a 16.994 second maximum. Queue-to-completion averaged 8.878 seconds. Acquisition processes totaled 154.781 seconds, compared with 0.839 seconds for parsing/detection/database work and 99 seconds of requested dwell. Host CPU averaged 32.4%, peaking at 53.8%; other validation workloads ran concurrently, so these are not scanner-process CPU figures.

The 1.3 campaign lasted 920 seconds, produced 127.75 MHz gross and the same 12.25 MHz unique valid coverage, 272 observations, 81 candidates, five completed investigations and two verified RDS recordings. The shorter new run cannot establish better RF sensitivity, unique-coverage speed or device identification. Revisit coverage dominates after the configured windows have been explored. Candidate decisions retain weak-signal, capture-disabled, cooldown and FM-passband deferrals; no synthetic jobs inflate completion counts. Native RDS PI/Program Service provenance and conservative identity rules remain unchanged. ADS-B and AX.25 fixtures retain checksum validation; current field conditions did not establish new verified aircraft, packet stations or sensor devices. DMR/P25/NXDN verification and digital voice remain unsupported pending validated per-frame integrity adapters.

Implementation is original MIT-licensed Python/JavaScript using the existing NumPy/SciPy dependencies and browser Web Audio. No third-party receiver or decoder source was copied. [SDR++](https://github.com/AlexandreRouma/SDRPlusPlus) was used as a functional reception-control reference; it is GPL-3.0 and is not bundled. [cnn-rtlsdr](https://github.com/randaller/cnn-rtlsdr), the [SDR tool showcase](https://github.com/gyaresu/sdr) and [rtl-entropy](https://github.com/pwarren/rtl-entropy) were reviewed for capability context; none was incorporated or installed. DSP remains the default classifier and no ML training was added.

Private hardware/browser screenshots, raw campaign measurements, preserved database snapshots, detailed validation logs and the consolidated release record remain outside the public package. Ubuntu 26.04 was not available through the configured validation host; no infrastructure was changed to provision it.

The main catalog remains exactly 746 channels, 1,513 observations, 16 captures and 21 identification revisions. Every original row was compared against a consistent pre-release SQLite snapshot, and all 16 capture files still match their recorded SHA256 digests. SQLite integrity is OK. The 744 UNKNOWN channels include 19 with observations in the last 24 hours having explicit UTC, 15 seen on multiple survey visits, 229 with historical peak SNR at least 10 dB, 515 below that level, and 733 without an identification analysis. These overlapping categories describe saved evidence, not current activity. Legacy timestamps lacking a timezone do not establish recency. The user's current enabled profiles grant no automatic capture permission for those channels; manual monitoring remains available for all of them. Spectral similarity and frequency never establish physical device identity.

Six additional matched AM probes at the same manual gain rejected all three coarse and all three finer-resolution attempts for non-finite power. A resolution change therefore is not presented as a repair. With the affected FM range excluded from both matched scanner arms, six valid visits covering 6.3 MHz took 29.789 seconds in the prior arm and 29.999 seconds in the current arm (0.21149 versus 0.21001 valid MHz/s). This small difference does not support a throughput improvement. The campaign's four invalid visits are explicitly categorized as non-finite/malformed power, not decoder failures.

The isolated Auto Survey transition test preserved 163 completed checkpoints, resumed discovery after monitoring and completed another checkpoint, then repeated restoration after an expired monitor lease. Receiver transfer took 2.782 seconds, including process shutdown and live startup. Both receiver and scheduler locks were acquirable after shutdown. The browser test selected a retained RDS channel and an UNKNOWN channel, checked live PCM playback and reception adjustments, saved a signal preset, recovered RDS in a live window, completed assisted reception, and verified that refresh stopped playback and released the abandoned monitor after lease expiry. No JavaScript errors occurred. The verification establishes browser audio processing and scheduling, not physical speaker audibility or communications intelligibility.

Longer audio testing exposed excessive full-waterfall serialization and heartbeat/control collisions. The monitor now sends incremental waterfall rows, renders a bounded bitmap, and renews its lease without competing for the receiver command lock. A 32.161 second listening measurement delivered 307 additional PCM batches, with four additional browser scheduling underruns and zero discarded-backlog batches. Browser queued audio ended at 239 ms and reported 32 ms output latency. These are downstream components, not a measured antenna-to-speaker delay. The application and receiver child used about 50.6% of one logical CPU and peaked at 340,140,032 bytes aggregate RSS; the browser is excluded from those process figures. Audio is functional but occasional scheduling gaps remain on this VM. Hardware retuning and assisted gain trials intentionally introduce further gaps. No dropout-free or calibrated end-to-end latency claim is made.

Streaming fixtures exercise every supported mode at all four advertised sample rates, including the exact 48 kHz intermediate-rate case, and verify exact output sample counts, finite processing, opposite-sideband suppression, clipping protection and squelch hysteresis. Last reception settings restore manual gain and PPM across application restarts without overwriting explicit user presets. Selecting a different inventory signal clears the prior fine offset unless that signal has a saved preset.

Final release checks: Windows passed **241 tests** in 94.811 seconds. Ubuntu 24.04 ran **228 tests**, with **224 passing and four skips**, in 56.505 seconds. The installed Ubuntu wheel ran **77 tests**, with **73 passing and four skips**, in 21.489 seconds. Skips cover the Windows-only Job Object branch and three integrations requiring the optional rtl_433 binary absent on that host. Windows also runs 13 existing local tests intentionally excluded from the public source package. All six modes acquired fresh hardware I/Q at 2.4 MS/s without receiver or DSP failure; this confirms the streaming path, not real-world AM/SSB/CW intelligibility. WFM browser playback remains the field audio validation. Final localhost shutdown checks released the receiver and scheduler locks. Public index, wheel and source archive checks found zero automated publication findings; private RF evidence was not transferred to Ubuntu or included in packages. No GitHub push was performed.
